# 배포 검증 (2026-10-15)

- 현재 PC의 본 최적화 프로세스가 없는 것을 확인했습니다. 새 본 런은 시작하지 않았습니다.
- 완료된 step 200 / 업데이트 200 / Adam 200을 확인했습니다. 종료 이유는 오류가 아니라 `step_budget`입니다.
- checkpoint 압축·분할 후 새 출력 폴더에 다시 복원했습니다.
- 원본 `state.pt`, `best_state.pt`, `best_binary.npz`, `history.json`의 SHA256이 복원본과 일치했습니다.
- theta, Adam m, Adam v의 float64 배열 해시가 원본과 일치했습니다.
- 광학 runner 및 포함된 수치 의존 소스의 해시가 원래 코드와 일치했습니다. 보고 함수만 외부 wrapper로 교체했습니다.
- 단위 테스트 5개 통과: 코드 보존, 200→270 실행 인자, 보고 함수 연결, 완료 런 연장 시 Adam/밀도 정확 일치, 소형 실제 RCWA forward/backward의 유한값 검사.
- 완료 후 연장 테스트는 작은 mock objective에서 연속 4회와 2회 완료 후 재개한 4회의 theta/m/v가 완전히 일치함을 확인했습니다. 이는 실제 full-size gradient 검증을 대체하지 않습니다.
- 전체 4 µm 구조의 추가 GPU 계산은 이 PC에서 실행하지 않았습니다. 새 GPU에서 step 200 재평가부터 시작합니다.
- HTML 확인: 1440 px 및 390 px 화면에서 가로 넘침·JavaScript 오류 없음, 그래프/3D 이미지 정상, 학습 4개와 검증 3개 행 표시.
- 원래 개발용 PyTorch 환경에서 검사했습니다. 새 PC 설치 스크립트의 stable PyTorch 2.9.0 환경에서도 작은 테스트를 다시 실행하도록 했습니다. 새 GPU에서의 동일 수치 결과는 아직 검증되지 않았습니다.
